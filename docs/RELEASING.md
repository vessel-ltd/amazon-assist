# 配布ZIPの検証とリリース

## 自動で確認する範囲

[GitHub Actions](https://github.com/vessel-ltd/amazon-assist/actions/workflows/verify.yml) は、mainへのpush、Pull Request、手動実行、`v*`タグへのpushで動きます。

1. Node.js 24で依存をインストールし、取得用スクリプトをビルドします。コミット済みの生成ファイルと違えば失敗します。
2. 架空の注文による解析・取得待ち・診断ログのテストと、配布ZIP検証のテストを実行します。
3. Git管理下の拡張ファイルとLICENSEからZIPを作成します。参照先のファイル不足、バージョン不一致、想定外のファイルやパス、外部スクリプトの参照を検出します。
4. ZIPを一時フォルダーに展開し、**そのZIPに含まれるコード**で、拡張ボタンからの起動、年月の指定、複数ページの注文取得、領収書取得、印刷プレビュー作成、印刷要求、診断ログ保存までを確認します。途中失敗による部分出力の防止と、注文のない月も確認します。
5. ZIPとSHA-256チェックサムをActionsの `install-zip` 成果物に保存します。保持期間は14日です。

4はjsdomと模擬Chrome APIによるテストです。Amazonへの通信、実Chromeへの拡張インストール、印刷画面の操作、PDFファイルの保存は行いません。**Actions成功だけで実Chromeの通しテストが完了したことにはなりません。** 実注文データ・ログイン情報・秘密情報はCIに渡しません。

手元ではNode.js 22以上とPython 3で実行できます。

```sh
npm ci
npm run build
git diff --exit-code -- extension/reader-content.js
npm test
npm run package
npm run test:package
```

生成物は `output/store/amazon-assist-バージョン.zip` と、その `.zip.sha256` です。ZIPのファイル順・日時・属性を固定しています。同じソースとビルド環境からは同じZIPを生成できます。チェックサムは破損・相違の検出用で、作者による電子署名ではありません。

## 実Chromeでの新規インストール確認

更新済みの開発フォルダーだけで済ませず、配布するZIPを別の永続フォルダーへ展開し、READMEの手順で新規に読み込みます。既存の拡張と混同しないよう、テスト中は既存の版を無効にしてください。Amazonアカウントはテストする本人のものを使います。

- [ ] 展開先にmanifestが直接あり、Chromeでエラーなく読み込める。
- [ ] 拡張機能メニューから開ける。画面・manifest・診断ログのバージョンが一致する。
- [ ] 注文がある月を選び、取得完了後の印刷画面でA4・PDF保存を指定し、保存できる。
- [ ] 保存したPDFを開き、対象月・注文数・注文番号・金額がAmazonの注文履歴と一致する。月の境界や一覧の2ページ目以降の注文も確認する。
- [ ] 複数ページになる注文、キャンセル済み・0円の注文がある場合、その説明と金額を含めて確認する。ない場合は「未確認」と記録する。
- [ ] 印刷の再表示ボタンと診断ログの手動保存が動く。診断の印刷要求をPDF保存成功と混同しない。
- [ ] 注文のない月、途中の中止、ログイン・確認が必要な場合を確認する。取得できていない注文を黙って省いたPDFを出さない。
- [ ] READMEの手動更新手順で、新版の画面と取得処理へ切り替わる。

テスト結果はChromeバージョン・OS・拡張バージョン・確認日・確認したケースだけを記録します。実PDF・注文番号・診断JSON・住所や支払い情報は公開リリースやIssueに添付しません。

## リリースを作る

1. manifest、画面、診断ログのバージョンを揃え、CHANGELOGへ変更内容を記載してmainへpushします。
2. Actions成功を確認し、上の実Chrome確認を行います。
3. 対象コミットへ `vバージョン` のタグを付けてpushします。
4. タグとZIPのバージョンが一致し、すべての自動確認が成功すると、ActionsがZIPとチェックサムを添付した **GitHub Releaseの下書き** を作成します。失敗した場合は下書きを作成しません。
5. 下書きの説明へ変更内容と検証結果を追記し、添付ZIPを確認して公開します。実Chromeで未確認のケースは明記します。

タグ例（実際の新版に置き換えます）:

```sh
git tag vX.Y.Z
git push origin vX.Y.Z
```

既に公開したタグ・添付ZIPは上書きせず、修正版のバージョンを作ります。同じタグのワークフローを再実行し、既にリリースがあれば、作成処理は失敗します。ストア申請・Googleへの提出はこのワークフローでは行いません。
